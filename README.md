# АИС «Заявки» v2.0 (Автоматизированная Информационная Система Учёта Заявок)

Полнофункциональная, безопасная веб-система для приёма, обработки, учёта и аналитики обращений технической поддержки пользователей. Разработана в соответствии со стандартами промышленной разработки на Python/Flask, требованиями безопасности OWASP Top-10 и регламентами SLA.

---

## 🌟 Ключевые возможности и архитектура

1. **Многоуровневая ролевая модель (RBAC):**
   - **Пользователь (`user`):** регистрация, создание заявок, отслеживание персонального реестра, просмотр SLA, добавление комментариев, закрытие решённых заявок.
   - **Специалист поддержки (`agent`):** сквозной реестр всех обращений, приём в работу, изменение статусов, назначение ответственных, удаление неактуальных заявок (с сохранением в аудит-журнале), аналитический дашборд.
   - *Безопасность ролей:* самостоятельное назначение роли `agent` при регистрации исключено. Назначение специалистов производится через защищённый административный CLI-скрипт.

2. **Регламент и контроль SLA:**
   - Автоматический расчёт дедлайна по единой формуле в зависимости от приоритета:
     - **Критический:** 4 часа
     - **Высокий:** 8 часов
     - **Обычный:** 24 часа
     - **Низкий:** 72 часа
   - Вычисление оставшегося времени или фиксация факта и длительности просрочки в реальном времени.

3. **Комплексная система безопасности:**
   - **Защита паролей:** алгоритм `PBKDF2-HMAC-SHA256` с 600 000 итераций и случайной криптографической солью (рекомендация OWASP).
   - **Защита от тайминг-атак:** константное время проверки паролей даже для несуществующих логинов (`DUMMY_PASSWORD_HASH`).
   - **Анти-брутфорс и Rate Limiting:** раздельное ограничение попыток входа (5 попыток за 5 минут), регистрации (3 за 10 минут) и отправки заявок/сообщений по хешированным идентификаторам клиентов.
   - **Защита сессий:** хранение криптостойких токенов в `HttpOnly`, `SameSite=Lax` Cookie с флагом `Secure` (при HTTPS). Автоматическая инвалидация старых сессий при новом входе и кнопка завершения сессий на всех устройствах.
   - **Автоматическая очистка:** удаление истёкших сессий и устаревших записей попыток.
   - **Защита от CSRF:** обязательная валидация криптографических токенов для всех мутирующих запросов (POST).
   - **Защита от Host-Header Injection:** встроенная валидация `request.host` по списку `TRUSTED_HOSTS`.
   - **Защита от Log Injection и утечки PII:** очистка спецсимволов перевода строки (`\r`, `\n`) и исключение персональных данных (тем заявок, описаний) из логов аудита (логируются только системные ID).
   - **Заголовки безопасности:**
     - `Server: AIS-Zayavki/2.0` (скрытие версий Werkzeug/Python)
     - `X-Content-Type-Options: nosniff`
     - `X-Frame-Options: DENY` (защита от Clickjacking)
     - `Referrer-Policy: strict-origin-when-cross-origin`
     - `Permissions-Policy: geolocation=(), camera=(), microphone=()`
     - `Content-Security-Policy: default-src 'self'; ...` (полная изоляция, без внешних CDN)
     - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (при `COOKIE_SECURE=1`)

4. **Высокая производительность базы данных:**
   - СУБД SQLite с включённым режимом WAL (`PRAGMA journal_mode = WAL`) и внешними ключами (`PRAGMA foreign_keys = ON`).
   - Составные индексы на часто фильтруемые поля (`author_id`, `assignee_id`, `status`, `created_at`, `kind+identifier_hash+created_at`).
   - Пагинация и поиск (`LIKE`) выполняются непосредственно в SQL, исключая загрузку всей БД в память.
   - Встроенный механизм версионирования схемы (`schema_version`) и автоматических миграций.

## 🚀 Быстрый старт и запуск

### 1. Требования к окружению
- Python 3.10 или выше
- СУБД SQLite 3.35+ (входит в стандартную библиотеку Python)

### 2. Установка зависимостей
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Для проверки безопасности установленных пакетов запустите аудит:
```bash
pip install pip-audit
pip-audit
```

### 3. Запуск приложения для разработки
По умолчанию приложение слушает порт **5000** на всех сетевых интерфейсах (`0.0.0.0`):
```bash
python app.py
```
После старта сервис доступен по адресу: **http://127.0.0.1:5000**

### 4. Запуск с демонстрационными данными
Для проверки функционала в демо-режиме (будут созданы аккаунты `support`, `ivanova`, `petrov` с паролем `demo1234` и 24 тестовые заявки):
```bash
SEED_DEMO=1 python app.py
```

### 5. Продакшн-развёртывание (WSGI)
Для эксплуатации в промышленной среде используйте `gunicorn` (Linux) или `waitress` (Linux/Windows):
```bash
# Через Gunicorn (4 рабочих процесса)
gunicorn -w 4 -b 0.0.0.0:5000 "app:app"

# Через Waitress
waitress-serve --port=5000 app:app
```
*Примечание:* Схема базы данных инициализируется автоматически внутри фабрики `create_app()`, поэтому сервис готов к работе под WSGI-сервером без дополнительных ручных шагов.

## 👥 Управление пользователями и назначение специалистов

В целях исключения уязвимостей эскалации привилегий веб-форма регистрации создаёт только учётные записи с базовой ролью `user`.

Для назначения или создания специалиста технической поддержки (`agent`) используется административный CLI-скрипт:
```bash

# Создать нового специалиста поддержки с заданным паролем:
python scripts/create_agent.py admin_support "SecurePass2026!"
```

## 🔒 Настройка HTTPS и обратного прокси (Nginx)

При развёртывании в продуктивной среде рекомендуется настроить Nginx в качестве обратного прокси с терминацией TLS.

Пример конфигурационного блока `/etc/nginx/sites-available/ais_zayavki.conf`:
```nginx
server {
    listen 80;
    server_name helpdesk.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name helpdesk.example.com;

    ssl_certificate /etc/letsencrypt/live/helpdesk.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/helpdesk.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location /static/ {
        alias /path/to/ais_zayavki/static/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
*Запуск сервиса с Nginx:*
```bash
export BEHIND_PROXY=1
export COOKIE_SECURE=1
export TRUSTED_HOSTS="helpdesk.example.com"
gunicorn -w 4 -b 127.0.0.1:5000 "app:app"
```

Для надёжного горячего резервного копирования без блокировки активных пользователей используется скрипт:
```bash
./scripts/backup.sh
```
Скрипт использует API `.backup` SQLite, сохраняет дамп с правами `0o600` в каталог `instance/backups/` и автоматически удаляет архивы старше 30 дней.

Настройка расписания в cron (ежедневно в 02:00):
```cron
0 2 * * * cd /path/to/ais_zayavki && ./scripts/backup.sh >> instance/backup.log 2>&1
```

## 📋 Справочник API и HTTP-маршрутов

| Метод | URL | Доступ (RBAC) | Назначение / Тело запроса | Ответ |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | `/healthz` | Все | Мониторинг работоспособности сервиса и доступности БД | JSON `{"status": "ok"}` |
| `GET` | `/login` | Анонимный | Отображение формы входа | HTML |
| `POST` | `/login` | Анонимный | Аутентификация: `username`, `password`, `csrf_token` | Redirect на `/` или 401 |
| `GET` | `/register` | Анонимный | Отображение формы регистрации | HTML |
| `POST` | `/register` | Анонимный | Регистрация: `username`, `password`, `confirm_password`, `csrf_token` | Redirect на `/` или 400 |
| `POST` | `/logout` | Авторизован | Завершение текущей сессии пользователя | Redirect на `/login` |
| `POST` | `/logout-all` | Авторизован | Инвалидация всех сессий пользователя на всех устройствах | Redirect на `/login` |
| `GET` | `/` | Авторизован | Реестр обращений с пагинацией и фильтрами (`q`, `status`, `priority`, `page`) | HTML |
| `GET` | `/add` | Авторизован | Отображение формы создания заявки | HTML |
| `POST` | `/add` | Авторизован | Создание обращения: `subject`, `description`, `priority`, `csrf_token` | Redirect на `/ticket/<id>` |
| `GET` | `/ticket/<id>` | Автор / `agent` | Детальный просмотр заявки, SLA-таймера, истории и комментариев | HTML (или 403/404) |
| `POST` | `/ticket/<id>/status` | Автор / `agent` | Обновление статуса заявки: `status`, `csrf_token` | Redirect на `/ticket/<id>` |
| `POST` | `/ticket/<id>/assign` | `agent` | Назначение исполнителя: `assignee_id`, `csrf_token` | Redirect на `/ticket/<id>` |
| `POST` | `/ticket/<id>/comment` | Автор / `agent` | Добавление комментария: `comment`, `csrf_token` | Redirect на `/ticket/<id>` |
| `POST` | `/ticket/<id>/delete` | `agent` | Удаление заявки с фиксацией в `deleted_log`: `csrf_token` | Redirect на `/` |
| `GET` | `/report` | `agent` | Сводный отчёт по нагрузке, распределению обращений и SLA | HTML |
